    T09 — Choosing an engine and checking convergence¶

    groundfield solves the same physical problem with several numerical methods (backends). They differ in the soils they accept, in how they represent the current on the wires, and in cost. This tutorial runs one problem through every engine, explains the differences, and shows how to check that a result has converged with respect to the discretisation — against an exact reference.

    You will learn

    • which backends exist, what they can do, and which names are deprecated aliases;
    • how to compare engines with gf.compare_engines;
    • the difference between the exact line-source kernel (the default of the image family) and the point kernel;
    • how to run and read a gf.convergence_study.

    Runtime: a few seconds.

    One problem, every engine¶

    Two 2 m rods, 4 m apart, bonded by an ideal conductor, in 100 Ω·m; 1 A into one of them. gf.compare_engines solves the world with every engine and tabulates impedances (real and imaginary part, every frequency) against a tolerance.

    How to read the table:

    • mom and mom_sommerfeld agree to all digits: in homogeneous soil they assemble the same system. Their agreement checks the Green's function (in layered soil), not the discretisation.
    • image and mom differ by a few percent. That is the difference between two current ansätze, not an error of either; for impedances both are acceptable, for fields next to extended electrodes mom is the better choice (tutorial T08).
    • The point kernel lies below the line kernel; the convergence study below shows which of the two is right.
    • fem is not in the table to keep this tutorial fast: two rods side by side are not on one axis, so fem solves them with its three-dimensional model, which needs the optional fem3d extra and about ten seconds and a gigabyte for this world. For a single rod, a ring or a ring with a central rod its axisymmetric model solves the electrodes as the solid bodies they are in a fraction of a second. Either way it is an independent reference (see the fem engine page).

    Capabilities are checked before the solve. Asking mom for the line-source kernel, for example, fails at once and names the backends that accept the request: image, which implements the line kernel, and fem, which has no source kernel of its own. fem solves the electrodes as solid bodies (in its three-dimensional model as smoothed line sources); the engine's kernel only selects how the point sources of its result evaluate the field afterwards, which is why the capability table above lists no kernel for it:

    Convergence against an exact reference¶

    For a straight rod of length \(L\) and radius \(a\) that starts at the surface and leaks a uniform current, the average-potential method (Howe; the method behind Dwight's formulas) gives the resistance as a closed form. Averaging the potential of the line current and of its image over the rod (reduced kernel \(1/\sqrt{(z - z')^2 + a^2}\)),

    \[ R = \frac{\rho}{4\pi L^2}\,(D + I),\qquad D = 2\Bigl[L\,\operatorname{arsinh}\frac{L}{a} - \sqrt{L^2 + a^2} + a\Bigr], \]
    \[ I = \sqrt{L^2 + a^2} - a + 2L\Bigl[\operatorname{arsinh}\frac{2L}{a} - \operatorname{arsinh}\frac{L}{a}\Bigr] - \Bigl[\sqrt{4L^2 + a^2} - \sqrt{L^2 + a^2}\Bigr]. \]

    Dwight's \(\frac{\rho}{2\pi L}(\ln\frac{4L}{a} - 1)\) is its limit for \(a \ll L\). This is the model of the image backend, so its result must converge to \(R\); we refine the segment length from 1 m to 6.25 cm with gf.convergence_study, which clones the engine for every segment length and tabulates the impedance.

    Copied! 
    RHO, L, A = 100.0, 3.0, 0.008


def rod():
    world = gf.create_world(soil=gf.HomogeneousSoil(rho=RHO))
    gf.create_electrode(
        world, "rod", name="rod", position=(0.0, 0.0, 0.0), length=L, wire_radius=A
    )
    gf.create_source(world, attached_to="rod", magnitude=1.0)
    return world


D = 2 * (L * np.arcsinh(L / A) - np.hypot(L, A) + A)
I = (
    np.hypot(L, A)
    - A
    + 2 * L * (np.arcsinh(2 * L / A) - np.arcsinh(L / A))
    - (np.hypot(2 * L, A) - np.hypot(L, A))
)
r_exact = RHO / (4 * np.pi * L**2) * (D + I)
print(
    f"exact uniform-current resistance: {r_exact:.6f} Ohm (Dwight: {dwight1936.rod(RHO, L, A):.6f} Ohm)"
)

    The line kernel integrates the potential of each segment exactly, so the uniform-current solution is reproduced at every segment length. The point kernel puts each segment's current into its midpoint; its error does not vanish under refinement — it converges to a value 1–2 % too low. The mom backend shares the point kernel and in addition lets the current vary along the rod; it drifts with the segment length and stays below as well. This is why the image family uses the line kernel by default since this release (kernel="point" reproduces the numbers of releases up to 0.15.0).

    Curved electrodes: chords converge with Δs²¶

    A ring is discretised into straight chords, so even the exact line kernel sees a polygon. The polygon converges to the circle with the square of the segment length: every halving of \(\Delta s\) should cut the change of the result by about four.

    Practical rules¶

    • Start with the default image engine; switch to mom for touch and step voltages next to extended electrodes, and to mom_sommerfeld for three or more soil layers.
    • Cross-check a new model once with a second engine and, where one exists, a closed form (Dwight, IEEE Std 80) or a limit (homogeneous soil, very thick or thin layers).
    • Run a convergence_study on a representative geometry of your study and choose the coarsest segment length whose change per halving is below your tolerance; with the line kernel 0.5–1 m is often enough for impedances.
    • Keep segments much longer than the wire radius, and let gf.diagnose(world, engine) check resolution, segment budget and close wires before a large run (see the how-to guide on warnings).
