    Changelog¶

    All notable changes to groundfield are documented in this file. The format is based on Keep a Changelog.

    These are concise release notes. The full narrative of every review and audit pass (findings, measurements, decisions) is kept verbatim in the audit history; work that is planned but not scheduled is on the roadmap. Up to 0.15.0 both stood in this file; they moved in 2026.11.0, and the release notes of 0.1.0 to 0.15.0 were condensed. The complete text as published is in the history of this file (for example at the tag v0.15.0).

    Versioning. From 2026.11.0 on, the project uses Calendar Versioning with the scheme YYYY.MM.MICRO in its PEP 440 form: the month has no leading zero and there is no hyphen, MICRO counts the earlier releases of the same month, and tags carry a v prefix. 2026.11.0 is the first release of November 2026, 2026.11.1 the second one, 2027.1.0 the first release of January 2027. Releases up to 0.15.0 followed Semantic Versioning.

    Deprecation policy. A calendar version carries no compatibility promise; compatibility follows this policy instead:

    • A deprecated name, parameter or behaviour keeps working and emits a DeprecationWarning that names its replacement and the earliest release in which it may be removed.
    • It is removed no earlier than two releases and six months after the release that announced the deprecation (announced in 2026.11.0: removed in 2027.5.0 at the earliest).
    • Every deprecation is listed under Deprecated in the release that announces it, every removal under Removed in the release that performs it.

    Categories. Each release lists its changes under Added, Changed, Deprecated, Removed, Fixed and Security. An entry marked ⚠ changes numerical results; from 2026.11.0 on, every release that moves numbers opens with a Numbers that change block (what moves, by how much, for whom, and how to get the old numbers back), and every Fixed entry names the test that fails on the previous release. Finding identifiers (F01–F57 of review pass 9, 10.01–10.95 of review pass 10) refer to the audit history.

    Contributing. Add your entry under the matching category of the [Unreleased] block; python scripts/release.py calver turns that block into the section ## [YYYY.M.MICRO] - YYYY-MM-DD of the new release.

    Security¶

    • BusType formulas are parsed, never executed (10.01). evaluate_spec passed impedance_formula to sympy.sympify, so a crafted BusType file ran code or exhausted memory. An allow-list parser (groundfield.io._formula) builds the expression from the syntax tree, every node unevaluated, computes its numbers itself in bounded floating point and evaluates it with its own numeric function instead of lambdify, with bounds on length, nodes, depth, number size, work and the product of nested exponents (64); formulas are validated on load (EvaluateSpecError), and crafted documents raise ValueError (metadata nested deeper than MAX_METADATA_DEPTH, fields of the wrong type), so every other entry point works on what the loader accepts (audit A3SG-04). (A first version still let SymPy expand symbolic exp and fractional powers of large powers: 67- to 75-character formulas ran longer than 60 s; second adversarial audit, A2G-01 to A2G-03.) Every formula the 0.15.0 exporter wrote still loads with the same value. The attack corpus tests/data/formula_corpus.json (119 accepted, 122 rejected) is shared with groundinsight's guard. Tests: tests/test_formula_security.py.
    • Result files from untrusted sources (audit A1-01). load_result decodes only the array types the encoder writes, checks shapes and sizes before allocating and bounds the nesting depth; a number beyond the float range raises ValueError (audit A2S-04). Tests: tests/test_result_metadata_codec.py.
    • Overpass requests (10.05). Validated parameters (no query injection through timeout_s), https only, a capped response (16 MiB by default), error payloads raise and are not cached, atomic cache files, every element checked before caching; payloads nested deeper than an Overpass result, ids beyond 64 bits and oversized integer coordinates raise OverpassError (audit A2G-05). Tests: tests/test_overpass_ingest.py.
    • Wheel contents (10.02). The wheel installed scripts/release.py and the release command like groundinsight 0.3.0 does, so installing both overwrote one with the other; it now ships only groundfield. Test: tests/test_packaging.py::test_wheel_contents.
    • Supply chain (10.03, 10.04). Workflows with minimal permissions and actions pinned to commit SHAs (Dependabot keeps them current), no persisted credentials, tag names only through environment variables, the release gated by the full CI; locked dependencies updated until pip-audit reports no known advisory (last: tornado 6.6.1 for CVE-2026-126347, a dependency of the Jupyter tools in the dev and docs groups, not of the package).
    • Documentation site (10.08). MathJax 3.2.2 is vendored with the site and pinned by checksums, and no Google Fonts are loaded: the site requests no third-party resource. Test: tests/test_docs_assets.py.
    • VTK export (10.10). A newline in world.name can no longer break the file header; coordinates are written as double. Tests: tests/test_io_vtk.py::test_world_name_cannot_break_the_header, tests/test_io_vtk.py::test_points_are_double_precision_at_utm_scale.
    • Release tool (10.09). scripts/release.py runs git in the repository root, validates everything (also against the remote) before it writes and restores the files if the commit fails. Tests: tests/test_release_script.py.
    • FIPS builds (10.07). The penetration-mask hash uses md5(usedforsecurity=False); the digests and stored masks are unchanged. Test: tests/test_generator_reproducibility.py::test_mask_works_where_md5_is_blocked_for_security.
