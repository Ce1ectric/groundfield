    Geometry¶

    The geometry package describes the buried metal: parametric electrodes (rod, ring, strip, polyline, star, mesh, grid mesh), the leakage-free Junction node, and the discretisation of every electrode into straight wire segments that the solvers consume.

    Kind Class Parameters (m) Typical use
    rod RodElectrode position (top end), length driven rod (Tiefenerder)
    ring RingElectrode center, radius ring earth around a building or substation
    strip StripElectrode start, end horizontal earth strip, counterpoise
    polyline PolylineElectrode vertices, closed foundation earth following a building outline
    star StarElectrode center, n_arms, arm_length, orientation_deg star earth (Sternerder)
    mesh MeshElectrode corner, size, spacing mesh with a given spacing
    grid_mesh GridMeshElectrode corner, size, n_x, n_y substation grid with a given number of wires

    Every kind also takes wire_radius (default 5 mm) and concrete_shell_coefficient_ohm_m (default 0, see below).

    Mathematical and physical context¶

    An electrode is a thin wire: its radius \(a\) is small against its length and against the distance to other wires, so the current leaving the surface can be represented by a current on the wire axis and the potential is evaluated on the surface (at distance \(a\)). Each geometry is cut into straight segments

    \[ \Gamma_i = \{\mathbf{x}_i^{(0)} + \xi\,(\mathbf{x}_i^{(1)} - \mathbf{x}_i^{(0)}) : \xi \in [0, 1]\}, \qquad i = 1 \ldots N, \]

    no longer than Engine.segment_length. Grid and mesh wires are split so that wire crossings fall on segment end points, and every wire is cut at the soil-layer interfaces so that each segment lies in one layer; every interface cut is kept, however short the piece beyond it, so a rod tip that reaches a few millimetres into a layer is in contact with it. (The thin wire has no end face, so a rod end within one wire radius of an interface is a limit of the model — up to +21 % against the solid rod — and warns with InterfaceContactWarning; see the image_2layer page.) How the current is distributed over the segments — uniform per unit length on each electrode (image family) or one unknown per segment (mom family) — is a property of the backend, see Solver and source kernels.

    Concrete encasement. A foundation earth in concrete adds the radial resistance of the concrete shell. Every electrode kind carries it as a per-length coefficient

    \[ C = \frac{\rho_c}{2\pi}\,\ln\frac{a + t}{a} \quad [\Omega\,\mathrm{m}], \]

    for concrete resistivity \(\rho_c\), bare wire radius \(a\) and shell thickness \(t\); the electrode's wire_radius is then the outer radius \(a + t\) (the soil sees the shell surface), and every segment of length \(\Delta s\) adds the series resistance \(C/\Delta s\) of its shell to its self term. Only the image family (image, image_2layer) and solve_mutual_* represent a non-zero coefficient; the other backends reject such a world before they run. The helpers concrete_shell_coefficient, shell_resistance_from_coefficient and shell_coefficient_from_resistance convert between the coefficient and a lumped resistance; the physics is explained in concrete shells and ADR-0012.

    Validity. Thin-wire approximation (\(a \ll\) segment length and wire spacing); wires must be in the soil (\(z > 0\)) — the solver rejects segments in the air and warns about leakage segments that are long compared with their depth.

    Example¶

    import groundfield as gf
from groundfield.references import dwight1936

world = gf.create_world(soil=gf.HomogeneousSoil(rho=100.0))
star = gf.create_electrode(
    world, "star", name="star", center=(0.0, 0.0, 0.5), n_arms=4, arm_length=5.0
)
gf.create_source(world, attached_to="star", magnitude=1.0)
result = gf.create_engine(segment_length=0.5).solve(world)

assert abs(star.total_length() - 20.0) < 1e-12       # four arms of 5 m
R = result.input_impedance()[0].real                  # 10.05 Ω
R_ref = dwight1936.n_point_star(rho=100.0, arm_length=5.0, radius=0.005, depth=0.5, n_arms=4)
assert abs(R - R_ref) / R_ref < 1e-3                  # Dwight (1936), Eqs. 23-26

    The geometry queries segments(ds), segment_count(ds), wire_polylines(), bounds(), total_length() and min_feature_length() are available on every electrode without a solve, for example to check a model before a long computation.

    API reference¶

    geometry ¶

    Geometries of electrodes and grounding systems.

    This subpackage provides the 3-D geometry of the grounding system: the standard parametric electrode geometries and their discretisation into straight wire segments (WireSegments), which every electrode produces itself through segments(ds).

    Contents

    RodElectrode, RingElectrode, StripElectrode, PolylineElectrode, StarElectrode, MeshElectrode, GridMeshElectrode Parametric standard electrode geometries. Each answers the geometry queries segments(ds), segment_count(ds), wire_polylines(), bounds(), total_length() and min_feature_length(). Electrode Discriminated union over all electrode types. WireSegments Midpoints, lengths and unit tangents of a discretised wire geometry.

    Notes

    The geometry layer is deliberately decoupled from the solver, so the same geometry can be fed into the image-charge backend, MoM, or FEM.

    GridMeshElectrode ¶

    Bases: _ElectrodeBase

    Rectangular meshed earth electrode with explicit n × m divisions.

    Defines an axis-aligned rectangle of size (dx, dy) at depth corner[2], divided into n_x × n_y internal meshes. The geometry consists of n_x + 1 longitudinal wires (running along the local \(x\) axis from corner to corner + (dx, 0)) and n_y + 1 transverse wires (running along the local \(y\) axis). All wires share the same depth.

    Attributes:

    Name Type Description
    corner Point3D

    Corner point (x, y, z) in metres (min-x, min-y, depth).
    size tuple[PositiveLength, PositiveLength]

    Extent (dx, dy) of the rectangle in metres.
    n_x int

    Number of meshes along \(x\) (must be ≥ 1). The number of longitudinal wires is n_y + 1.
    n_y int

    Number of meshes along \(y\) (must be ≥ 1). The number of transverse wires is n_x + 1.
    concrete_shell_coefficient_ohm_m float

    Per-length concrete-shell coefficient in Ω·m (ADR-0012, default 0: no shell); see concrete_shell_coefficient().
    Notes

    Naming convention: n_x × n_y is the count of meshes (cells), not of wires. A grid with n_x = n_y = 1 is therefore a single closed rectangle (the perimeter wires only).

    PolylineElectrode ¶

    Bases: _ElectrodeBase

    Buried wire following an arbitrary horizontal polyline.

    Generalises StripElectrode from a single straight wire to a chain of straight wires through vertices. With closed = True the last vertex is wired back to the first, which makes this the Ringerder along an arbitrary building outline — the DIN-18014 Streifenfundament that follows the real building perimeter instead of its bounding rectangle.

    All vertices must lie at the same depth (the wire is horizontal), consistent with StripElectrode.

    Attributes:

    Name Type Description
    vertices list[Point3D]

    Ordered polyline vertices (x, y, z) in metres, at least two. For closed = True do not repeat the first vertex at the end — the closing edge is implicit.
    closed bool

    Whether the polyline is closed into a ring (default True).
    Notes

    Motivation (AP1): approximating a building footprint by its oriented bounding rectangle (OMBR) overestimates the electrode perimeter for L- and U-shaped buildings and — worse — lets the rectangles of neighbouring buildings coincide or overlap, which drives distinct segments into the solver's 1 mm singularity clamp. Following the real polygon removes both artefacts by construction.

    def segments(
    self, ds: float, layer_interfaces: Sequence[float] | None = None
) -> WireSegments:
    """Horizontal ring: ``max(8, ceil(2πr/ds))`` equal arcs (see base class).

    Each arc is represented by its midpoint on the circle, its arc
    length and the tangent there.
    """
    perimeter = 2.0 * np.pi * self.radius
    n = _segment_count(perimeter, ds, minimum=8)
    seg_len = perimeter / n
    cx, cy, cz = self.center
    mids = np.empty((n, 3))
    dirs = np.empty((n, 3))
    for k in range(n):
        # Scalar trigonometry, kept from the historic discretiser so
        # the midpoints stay bit-identical across platforms.
        phi = 2.0 * np.pi * (k + 0.5) / n
        mids[k] = (
            cx + self.radius * np.cos(phi),
            cy + self.radius * np.sin(phi),
            cz,
        )

    def segments(
    self, ds: float, layer_interfaces: Sequence[float] | None = None
) -> WireSegments:
    """Straight strip: equal segments along the axis (see base class).

    A sloped strip whose depth range crosses a layer interface would
    be split there first (ADR-0007 step 1); the model validator
    keeps strips horizontal, so this only guards the invariant.
    """
    L = self.length
    p0 = np.array(self.start, dtype=float)
    p1 = np.array(self.end, dtype=float)
    direction = (p1 - p0) / L
    # Map interface depths to axis parameters t in [0, L].
    t_cuts: list[float] = []
    dz = p1[2] - p0[2]
    if layer_interfaces and abs(dz) > 1e-12:
        for h in layer_interfaces:
            t_cuts.append((h - p0[2]) / dz * L)
    intervals = _split_interval_at_interfaces(0.0, L, t_cuts)
    # The length comes from the end points: allow their round-off.
    scale = _coordinate_scale(p0, p1)
    parts = []
    for t_lo, t_hi in intervals:
        part_len = t_hi - t_lo
        n = _segment_count(part_len, ds, scale=scale)
        parts.append(_straight_wire(p0, direction, t_lo, part_len / n, n))
    return WireSegments.concatenate(parts)

    @classmethod
def concatenate(cls, parts: Iterable[WireSegments]) -> WireSegments:
    """Join several containers in order.

    The wire indices are kept as they are (no offset): the parts of
    one wire cut at a layer interface stay one wire. A caller that

        wires = np.concatenate([p.wire_index for p in parts])

        np.concatenate([p.midpoints for p in parts], axis=0),
        np.concatenate([p.lengths for p in parts]),
        np.concatenate([p.directions for p in parts], axis=0),
        wires,
    )

    def concrete_shell_coefficient(
    rho_c: float, wire_radius: float, thickness: float
) -> float:
    r"""Per-length coefficient of a cylindrical concrete shell (ADR-0012).

    .. math::

        C = \frac{\rho_c}{2\pi}\,\ln\frac{r_a + t}{r_a}

    Parameters
    ----------
    rho_c
        Resistivity of the concrete in Ω·m, ``>= 0``.
    wire_radius
        Radius :math:`r_a` of the bare wire in m, ``> 0``.
    thickness
        Radial thickness :math:`t` of the shell in m, ``>= 0``.

    Returns
    -------
    float
        :math:`C` in Ω·m; ``0.0`` for ``rho_c = 0`` or ``thickness = 0``.

    Raises
    ------
    ValueError
        If an argument is negative or not finite, or ``wire_radius`` is
        not positive.

    Notes
    -----
    The electrode then carries ``wire_radius = r_a + t`` and
    ``concrete_shell_coefficient_ohm_m = C``. For ``rho_c = 100`` Ω·m and
    5 cm of concrete around a 5 mm wire, :math:`C` = 38.16 Ω·m.
    """
    values = {"rho_c": rho_c, "wire_radius": wire_radius, "thickness": thickness}
    for name, value in values.items():
        if not math.isfinite(float(value)) or float(value) < 0.0:
            raise ValueError(f"{name} must be finite and non-negative, got {value!r}.")
    if float(wire_radius) <= 0.0:
        raise ValueError(f"wire_radius must be positive (m), got {wire_radius!r}.")
    r_a = float(wire_radius)
    return float(rho_c) / (2.0 * math.pi) * math.log((r_a + float(thickness)) / r_a)
